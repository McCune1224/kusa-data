# Plan: Player Search + Lucky Stats-style Analytics

## Goal

Transform kusa-data from a tournament browser into a full player analytics platform. Users should be able to search for any Smash Ultimate player by gamer tag and see a comprehensive dashboard of stats (win/loss, set history, character usage, placement trends, H2H, etc.), similar to https://luckystats.gg/.

## Current State Summary

- Player lookup only works by **numeric start.gg user ID** (`/players/123456`), not by gamer tag
- Player search API at `/api/players` is a **dead stub** (returns `null`)
- Tournament history works (paginated, Redis-cached) but only 1 page of 20 is fetched
- No set/match data is fetched at all — we get placements but not scores, games, characters, stages
- Several type bugs exist (e.g., `TournamentRecordEvent.slug` typed as `number` but returns string; `PlayerEventStandingResponse` has the wrong nesting)
- `EventResult.svelte` has dead code and a broken 4th-place color check
- No Elo, no W/L, no character stats, no H2H — just raw placement history
- start.gg API supports all missing data via `player.sets()`, `game.selections.character`, `game.stage`, `set.displayScore`, `player.rankings()`, etc.

### Phase 2 — Set/Match Data (the foundation of all stats)

**Goal**: Fetch actual set/match data for players so we can compute W/L, scores, character usage, stage stats, etc.

**New/Modified files:**

- `src/lib/startql/player.ts` — Add `getPlayerSets(playerId)` and `getPlayerSetHistory(playerId, page, perPage)`
- `src/lib/startql/result_types.ts` — Add types for `Set`, `Game`, `GameSelection`, `Stage`, `StandingStats`
- `src/lib/startql/player.ts` — Add `getEntrantSetHistory(entrantId, page, perPage)`

**start.gg API needed:**

```graphql
query PlayerSets($playerId: ID!, $page: Int!, $perPage: Int!) {
	player(id: $playerId) {
		id
		gamerTag
		sets(page: $page, perPage: $perPage) {
			nodes {
				id
				displayScore
				fullRoundText
				state
				phaseGroup {
					id
					displayIdentifier
				}
				event {
					id
					name
					slug
				}
				slots {
					id
					entrant {
						id
						name
					}
					standing {
						id
						placement
						stats {
							score {
								value
							}
						}
					}
				}
				games {
					orderNum
					stage {
						id
						name
					}
					winnerId
					selections {
						entrant {
							id
						}
						selectionType
						character {
							id
							name
						}
					}
					entrant1Score
					entrant2Score
				}
				completedAt
				vodUrl
			}
			pageInfo {
				total
				totalPages
			}
		}
	}
}
```

**Key considerations:**

- Sets can have 1 or 2 slots (1 = bye, 2 = actual match)
- `displayScore` is a string like "3 - 1"
- `state`: 1=created, 2=active, 3=completed
- Games are individual matches within a set (bo3/bo5)
- Character data requires bracket reporters to enter it — not all tournaments have it
- `max 1000 objects per request` — a single set query can be object-heavy with nested games+selections. Keep `perPage` low (20-25).

**Caching strategy:**

- Cache set history in Redis with a longer TTL (maybe 15-30 min) since sets don't change once a tournament ends
- Cache key: `playerSets:{playerId}:{page}`

### Phase 3 — Stats Computation Engine

**Goal**: Compute meaningful statistics from raw set data.

**New files:**

- `src/lib/stats/` directory — Stats computation utilities
  - `winLoss.ts` — W/L record, win %, streak tracking
  - `characterStats.ts` — Per-character usage count, win rate per character
  - `stageStats.ts` — Stage picks and performance per stage
  - `placementTrends.ts` — Average placement, placement over time
  - `h2h.ts` — Head-to-head matchups between specific players
  - `elo.ts` — Simple Elo rating computation
  - `streaks.ts` — Current/season win/loss streaks

**Stats to compute:**

| Stat               | Source                                                              | Logic                                                     |
| ------------------ | ------------------------------------------------------------------- | --------------------------------------------------------- |
| Overall W/L        | `set.displayScore` or `set.slots[].standing.stats.score.value`      | Count wins vs losses from completed sets (exclude byes)   |
| Win %              | W/L totals                                                          | `wins / (wins + losses) * 100`                            |
| Current streak     | Sets sorted by `completedAt` desc                                   | Count consecutive W or L                                  |
| Best streak        | All sets                                                            | Longest consecutive W streak ever                         |
| Character usage    | `game.selections[].character.name`                                  | Count per character, % of total games                     |
| Character win rate | `game.winnerId` matched to character                                | % wins when using each character                          |
| Stage frequency    | `game.stage.name`                                                   | Count per stage                                           |
| Stage win rate     | `game.winnerId` matched to stage                                    | % wins on each stage                                      |
| Average placement  | `event.entrants.nodes[].standing.placement` from tournament history | Mean placement across all events                          |
| Placement trend    | Placements over time                                                | Simple linear trend                                       |
| H2H vs opponent    | Sets filtered by opponent playerId                                  | W/L record, last 5 results, set scores                    |
| Elo rating         | All completed sets                                                  | K-factor = 32, starting Elo = 1500, update after each set |
| Set count          | Total completed sets (excl. byes)                                   | Aggregate                                                 |
| Tournament count   | Unique tournaments played                                           | `userTournamentHistory`                                   |
| Top placements     | Best placements                                                     | Sort placements ascending, show top 5                     |
| Net set wins       | Wins - Losses                                                       | Differential                                              |

**Architecture decision:**

- Compute stats **on request** from cached raw data (no background jobs) — simpler to start
- Cache computed stats with shorter TTL (1-2 min) if they become expensive
- Use pure functions with no side effects for testability

**Goal**: Add the remaining Lucky Stats features.

   - Deep-dive into matchup between two players

3. **Player Rankings** (global + regional)

   - `/rankings` route with filterable table

   - `/tournaments` page showing all Smash Ultimate tournaments

   - Links to tournament detail pages with upset tracking

5. **Character Browser** (`/characters`)

## Key Risks & Mitigations

| Risk                                                                  | Mitigation                                                                                          |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| **start.gg rate limit** (80 req/60s)                                  | Cache aggressively. Batch queries. Stale-while-revalidate pattern.                                  |
| **1000 objects/request limit**                                        | Keep `perPage` low (20-25 for sets with nested games). Paginate aggressively.                       |
| **Character data is sparse** (requires bracket reporters)             | Show "no data" state gracefully. Don't gate other features on it.                                   |
| **Set data can be very large** (players with thousands of sets)       | Paginate set history. Cache computed stats so full scan only happens once.                          |
| **Elo computation is O(n) across all sets**                           | Compute incrementally (start from cached Elo, only process new sets). Background compute if needed. |
| **GraphQL query complexity** with deeply nested sets+games+selections | Test queries against the API with a real player first. Adjust fields if hitting limits.             |
| **No test framework** means manual testing for now                    | Spot-check after each change. Consider adding vitest for `src/lib/stats/` pure functions.           |
